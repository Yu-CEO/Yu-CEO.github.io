# 入口ページ（portal）

TikTok・LINEから来た人が、Yuの自己紹介と無料ツールの一覧を1ページで見て、使いたいツールへ移動するための入口ページです。
AI役員との毎日の会議を短くまとめた「経営会議の日記」（`/diary/`）も読めます。
公開先：https://yu-ceo.github.io/ （リポジトリ `Yu-CEO.github.io`）

## できること
- 1画面に1テーマの全画面パネルを、上から ①自己紹介（ヒーロー） ②ツール（1件1枚） ②' 最新の日記 ③LINE ④注意書き の順に並べる
- ヒーロー：夜の紺の背景（CSSだけで描く）に、小見出し・表示名・肖像（`assets/yu.jpg`）・プロフィール文・「TikTokを見る」・ボタン2つ（「無料ツールを見る」「オープンチャットに参加」）を表示する
- ツール一覧のデータ（`js/tools_data.js`）から、ツールごとのパネル（名前・一言説明・状態・スクリーンショット・「開く」ボタン）を作る。0件なら「ただいま準備中です」を出す
- 一覧のデータの形を検査し、正しくない項目は表示せず、ブラウザのコンソール（開発者用の画面）に理由を日本語で出す。画像の項目だけが正しくないときは、画像なしで表示する
- 設定ファイルのURLが正しいときだけ、TikTok・LINEのボタンを表示する。LINEのURLが2つとも使えないときはLINEパネルごと隠す
- ページ下部に、共通の注意書きを表示する
- **経営会議の日記**：`diary/entries/` の日記データから、入口ページの「最新の日記」パネル・ヒーローの「会議の日記」ボタン・一覧ページ（`/diary/`）・1件のページ（`/diary/entry.html?date=YYYY-MM-DD`）を作る。データは表示の前に検査し（決まった形か・金額やURLなど公開してはいけない書き方がないか）、正しくない日記は出さない。日記が1件もない・読み込めないときは、入口ページのパネルとボタンを隠す

## 使い方
1. `index.html` をブラウザで開く（サーバー・インターネット接続は不要）
   - **日記を手元で見るとき**：日記はデータ（JSON）を読み込むので、ファイルを直接開くと出ない（入口ページでは日記のパネルだけが隠れ、ほかは表示される）。このフォルダで `python -m http.server 8000` を実行し、ブラウザで http://localhost:8000/ を開く
2. **ツールを増やすとき**：`js/tools_data.js` の配列に1件足す（`name`・`description`・`url`（`https://` で始まる）・`status`（`"公開中"` か `"準備中"`））。ほかのファイルは触らない
   - スクリーンショットを載せるときは、画像を `assets/` に置き、`image: "assets/ファイル名"` と `imageAlt: "画像の短い説明"` を足す（`imageAlt` がないと「（ツール名）の画面」になる）。外部のURLや `..` を含む場所は使えない（画像なしで表示される）
3. **LINE・TikTokのURLを変えるとき**：`js/site_config.js` の該当する1行を書き換える。空（`""`）にするとそのボタンは消える
4. **文言（自己紹介・LINEパネル・注意書き）を変えるとき**：`index.html` を直す（日記のページの注意書きは `diary/index.html` と `diary/entry.html`）
5. **日記を足すとき**：`diary/entries/YYYY-MM-DD.json` を1つ作り、`diary/entries/index.json` の配列にその日付を1つ足す。形は下の「日記のデータの形」。`node --test` で検査を通ることを確かめてから、通常の手順（レビュー・確認・承認のあとでアップロード）で公開する
   - Day 1（2026-11-14）・Day 2（2026-11-15）のさかのぼりの日記も、同じ形で足し、同じ通常の手順で公開する（自動では公開しない）
6. **テスト**：このフォルダで `node --test`（Node.js 20 以上。外部ライブラリは不要）

## 日記のデータの形（`diary/entries/YYYY-MM-DD.json`）
| 項目 | 内容 | 決まり |
|---|---|---|
| `date` | 会議の日 | `YYYY-MM-DD`。ファイル名と同じ |
| `title` | 見出し | 空でない・40文字以内 |
| `summary` | 秘書の一言まとめ（一覧・パネルの抜粋） | 空でない・120文字以内 |
| `agenda` | 今日の議題（文字の配列） | 1〜3個・各60文字以内 |
| `lines` | 一言セリフ `{ "speaker": 話者, "text": セリフ }` の配列 | 2〜8個・各80文字以内。話者は「秘書」「アオイ」「CMO」「プロデューサー」「ブランドディレクター」「CFO」「CTO」「CISO」「Yu」だけ |
| `decisions` | 今日の決定（文字の配列） | 0〜5個・各80文字以内 |
| `lessons` | 今日の失敗・学び（文字の配列） | 1〜3個・各100文字以内 |
| `pick` | 冒頭の「今日の一言」に出すセリフの番号（1から数える） | 書かなくてよい。書くなら 1〜セリフの数 の整数。書かないと、秘書・Yu 以外で最初のセリフになる |

- 上の項目以外は書かない（書くと検査で止まる）。本文の合計は300〜1,500文字。Day N は日付から自動で計算する
- 検査で止まる書き方：`<` `>`・URL・メールアドレス・数字のあとに「円」「万」「億」（漢数字も含む）・数字や「〇」のあとに「室」「部屋」・投資を勧める言い回し。金額は「〇万円」「数万円」「ある金額」のように伏せる
- テスト用の仮の日記の例：`tests/fixtures/diary_entries/`（公開されない）

## 注意
- このサイトのツールは計算するだけのもので、特定の商品や売買をすすめるものではありません（投資の助言ではありません）。
- 外部ライブラリ・アクセス解析・外部への通信はありません。入力内容の保存・送信もしません（外部へのリンクを押したときの移動を除く）。読み込むのは同じサイトの日記のデータと顔の絵だけです。
- 日記は、AIを使った役員会議の記録を公開用に書き直したものです。金額などの数字は伏せています。登場する役員はAIのキャラクターです。
- 公開リポジトリです。コード・コメント・ドキュメントには、外に出せない情報を書かないでください。
