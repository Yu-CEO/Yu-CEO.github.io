# 入口ページ（portal）

TikTok・LINEから来た人が、Yuの自己紹介と無料ツールの一覧を1ページで見て、使いたいツールへ移動するための入口ページです。
AI役員との毎日の会議を短くまとめた「経営会議の日記」（`/diary/`）も読めます。
公開先：https://yu-ceo.github.io/ （リポジトリ `Yu-CEO.github.io`）

## できること
- 入口は上から ①何の人か＋指で塗れる絵＋ぬりえシアターのボタン ②AI役員（会議で実際に出た発言） ③経営会議の日記（本数と「売上は、まだ0」・最新1件・前の3件） ④無料の道具（1行目はぬりえ） ⑤LINE ⑥Yuの道具箱（PR） ⑦感想・仕事の相談 ⑧注意書き。画用紙と墨の配色で、日記・お問い合わせのページも同じ配色
- 「売上は、まだ0です（日付時点）」は自動で変わらない。受注したら `index.html` の文と日付を手で直す
- 塗れる絵：開くたびに絵3種×色5組が前回と違うものになる。端末に残すのは前回の番号だけで、塗った結果は保存しない。「動きを減らす」設定では線の動き・紙ふぶきを止める
- ツール一覧のデータ（`js/tools_data.js`）から、「会議から生まれた道具」に1ツール1行（名前・一言説明・スクリーンショット。行全体が押せる）で並べる。0件なら「ただいま準備中です」を出す
- 一覧のデータの形を検査し、正しくない項目は表示せず、ブラウザのコンソール（開発者用の画面）に理由を日本語で出す。画像の項目だけが正しくないときは、画像なしで表示する
- 設定ファイルのURLが正しいときだけ、TikTok・LINEのボタンを表示する。LINEのURLが2つとも使えないときはLINEパネルごと隠す
- ページ下部に、共通の注意書き（アクセス解析の説明を含む）を表示する
- **アクセス解析**：公開サイトで開いたときだけ、ページ別の閲覧数と参照元のサイト名を GoatCounter に送る（下の「アクセス解析（GoatCounter）」。送り先は `yuceo.goatcounter.com`）
- **Yuの道具箱**：Yuが実際に使っている証券口座・AIツール・開発の道具・本・ジムの設備を、ジャンル（お金・NISA → AI・開発の道具 → ふだん使い）ごとのカード（名前・Yuの一言・ボタン）で並べる。リンクの種類は「紹介リンク（PR）」「公式リンク」「リンクなし」の3つ。紹介リンクが1件でもあるときは、見出しの下に「この区画には広告（PR）を含みます」、そのカードに「PR」の印を出し、ASPの計測用の小さな画像（1×1）を置く。区画の下部に、体験談であること・投資の助言ではないこと・広告と計測の通信のことを書いた注意書きを出す（広告・計測の文は、紹介リンク・計測用画像があるときだけ）。表示できる道具が0件ならパネルごと隠す
- **経営会議の日記**：`diary/entries/` の日記データから、入口ページの日記の区画・一覧ページ（`/diary/`）・1件のページ（`/diary/entry.html?date=YYYY-MM-DD`）を作る。データは表示の前に検査し（決まった形か・金額やURLなど公開してはいけない書き方がないか）、正しくない日記は出さない。日記が1件もない・読み込めないときは、入口ページに「最初の日記は…」か「読み込めませんでした」（もう一度読み込むボタンつき）を出す

- **お問い合わせ**：入口の締めくくりの「感想・仕事の相談を送る」ボタン。押すと `contact.html`（受け付ける内容・返事は3日以内が目安・投資の個別相談は受けない・個人情報の扱い・半年を目安に削除）が同じタブで開き、そこの「フォームを開く（Google フォーム）」で新しいタブに Google フォームが開く。メールアドレスは載せない。ボタンのクリックは数えず、ページの閲覧数（`/contact.html`）だけ GoatCounter で数える。このページでは広告を出さない

## 使い方
1. `index.html` をブラウザで開く（サーバー・インターネット接続は不要）
   - **日記を手元で見るとき**：日記はデータ（JSON）を読み込むので、ファイルを直接開くと出ない（入口ページでは日記の区画が「読み込めませんでした」になり、ほかは表示される）。このフォルダで `python -m http.server 8000` を実行し、ブラウザで http://localhost:8000/ を開く
2. **ツールを増やすとき**：`js/tools_data.js` の配列に1件足す（`name`・`description`・`url`（`https://` で始まる）・`status`（`"公開中"` か `"準備中"`））。ほかのファイルは触らない
   - スクリーンショットを載せるときは、画像を `assets/` に置き、`image: "assets/ファイル名"` と `imageAlt: "画像の短い説明"` を足す（`imageAlt` がないと「（ツール名）の画面」になる）。外部のURLや `..` を含む場所は使えない（画像なしで表示される）
3. **LINE・TikTokのURLを変えるとき**：`js/site_config.js` の該当する1行を書き換える。空（`""`）にするとそのボタンは消える
4. **文言（自己紹介・LINE・売上の1文・注意書き）を変えるとき**：`index.html` を直す（日記のページの注意書きは `diary/index.html` と `diary/entry.html`）
5. **日記を足すとき**：`diary/entries/YYYY-MM-DD.json` を1つ作り、`diary/entries/index.json` の配列にその日付を1つ足す。2026-11-16 以降の日記は「新しい形」（`"format": 2`・1トピックの話）で書く。形は下の「日記のデータの形」。図がある日は `diary/figures/YYYY-MM-DD.svg` も置く（下の「日記の図」）。`node --test` で検査を通ることを確かめてから、通常の手順（レビュー・確認・承認のあとでアップロード）で公開する
   - Day 1（2026-11-14）・Day 2（2026-11-15）のさかのぼりの日記も、同じ形で足し、同じ通常の手順で公開する（自動では公開しない）
6. **道具箱の道具を増やす・リンクを差し替えるとき**：`js/toolbox_data.js` の配列だけを書き換える（項目の説明はファイルの先頭）。形が正しくない道具は表示されず、理由がコンソールに出る
   - **提携が承認されたとき**：ASPの管理画面のタグ（HTML）はそのまま貼らない。タグの中の「リンクのURL（`<a href="…">`）」と「計測用画像のURL（`<img src="…">` の1×1のもの）」の2つだけを写し、`linkType: "affiliate"`・`asp`（`"a8"` か `"moshimo"`）・`url`・`beaconUrl` を書く。`http://` のURLは `https://` にそろえる。表紙などの画像は使わない
   - URLのホスト名が `js/site_config.js` の `ASP_LIST` の `linkHosts`・`beaconHosts` にないと、リンク（または計測用画像）は出ない。そのときは `ASP_LIST` のホスト名を直す
   - **新しいASPを使うとき**：`ASP_LIST` に1件（`id`・`name`・`linkHosts`・`beaconHosts`）足す。ほかのJSは触らない
   - A8.net の計測用画像のホストは広告ごとに番号が違う（今は `www18.a8.net`）。新しいタグの番号が違うときは、`ASP_LIST` の `beaconHosts` に1つ足す。楽天市場用の紹介リンク（`rpx.a8.net`）には計測用画像がない
   - 文面には「おすすめ」「必ず」「儲かる」などの言葉は使えない（検査で止まる）。証券口座は体験として書き、比べない。酸素ルームは効き目を書かない
7. **テスト**：このフォルダで `node --test`（Node.js 20 以上。外部ライブラリは不要）
8. **アクセス解析**：下の「アクセス解析（GoatCounter）」
9. **お問い合わせフォームのURLを変えるとき**：`js/site_config.js` の `CONTACT_FORM_URL` の1行だけを書き換える。認めるのは `forms.gle` か `docs.google.com/forms` の `https://` のURLだけ（違う形・空だと、`contact.html` のフォームのボタンが消え、コンソールに直し方が出る）。フォームの説明文を直したら、`contact.html` の文も合わせる
10. **毎日の日記を自動で公開するとき**：下の「日記の自動公開（`tools/diary_publish.js`）」

## アクセス解析（GoatCounter）
> **Google タグマネージャー（2026-11-20 追加）**：公開サイトで開いたときだけ `js/gtm_loader.js` が GTM（`GTM_ID`）を読み込む。条件は下の GoatCounter と同じ。止めるときは `js/site_config.js` の `GTM_ID` を空にする。GTM の「カスタムHTML」タグは CSP で動かない。詳しくは `docs/requirements_analytics.md` 2-10

ページ別の閲覧数と、どのサイトから来たか（参照元）を知るために使う。外部のスクリプトは読み込まず、同じサイトのJS（`js/analytics_*.js`）が 1×1 の画像の読み込みで1回だけ送る（GoatCounter の公式ドキュメント「Tracking pixel」の `/count`）。
- **送るもの**：ページの場所（`p`。`#` 以降とクエリは送らない。日記1件だけ `?date=YYYY-MM-DD` の形の日付を付ける）・参照元のサイト名だけ（`r`。例 `https://www.tiktok.com`。パス・クエリは送らない）・キャッシュ回避の乱数（`rnd`）。画面の大きさ・題名・入力内容・Cookie は送らない
- **送らないとき**：`ANALYTICS_ENABLED` が `false`／`ANALYTICS_HOST` が空や形の違う値（コンソールに直し方が出る）／公開サイト（`https://yu-ceo.github.io`）以外で開いたとき（手元のサーバー・`file://`）／ブラウザが「トラッキングしない」（`doNotTrack` が `"1"`・`globalPrivacyControl` が `true`）／JavaScript が無効
- **止め方**：`js/site_config.js` の `ANALYTICS_ENABLED` を `false` にする（JSを消さなくてよい）
- **始め方**（サイトコードが決まったら）：
  1. `js/site_config.js` の `ANALYTICS_HOST` に `サイトコード.goatcounter.com` を書く（`https://` は書かない。英小文字・数字・ハイフンだけ）
  2. `index.html`・`diary/index.html`・`diary/entry.html` の CSP（`<meta http-equiv="Content-Security-Policy">`）の `img-src` に `https://サイトコード.goatcounter.com` を1つ足す（`*.goatcounter.com` のような広い書き方はしない）
  3. `ANALYTICS_ENABLED` を `true` にし、`node --test` が通ることを確かめる（1と2が食い違うと `tests/external_hosts.test.js` が失敗する）
- **サイトコードの決まり**：ページのソースに出る公開の値になるので、本名・会社名・仕事に関する言葉を入れない。ダッシュボードは非公開のまま。ログイン情報はコード・ドキュメントに書かない
- **CSP**（ページが読み込んでよい場所の制限）：4ページとも、スクリプト・スタイル・データは同じサイトだけ（`contact.html` は広告・道具箱の ASP のホストを入れない別の CSP）。外部は画像だけで、計測の送り先1つと、入口だけ道具箱の ASP の計測用画像のホスト（`ASP_LIST` の `beaconHosts`）。`ASP_LIST` を変えたら入口の CSP も直す（テストが一致を確かめる）。HTML に `style="…"` やインラインの `<script>` を書くと CSP で動かなくなるので書かない
- 外部の `<script>`・`<link rel="stylesheet">` を足すときは、`integrity`（SRI：中身が書き換えられていないかの確認）を必ず付ける（テストが確かめる）

## 共有カード・検索（説明文・sitemap・Search Console）
URL を LINE・X などに貼ったときの画像と説明（共有カード）と、Google の検索に全ページを見つけてもらうための仕組み。画面の見た目は変わらない。
- **説明文と共有カード**：4ページの `<head>` に `description`・`og:*`・`twitter:card` を書いている（先頭のコメント「共有カードと検索用の説明」の下）。文言を変えるときはそこを直す（120文字以内。`node --test` が文字数と書き方を確かめる）
- **日記1件のページ**：共有カードは全日共通（共有先は JS を動かさないため）。説明文だけ、表示のあとで `js/diary_page_meta.js` がその日の抜粋（`summary`）に書きかえる。日記が見つからないときは検索に載せない印（`noindex`）を付ける。`canonical`・`og:url` は書かない（書くと全日が1ページ扱いになる）
- **共有カードの画像**：`assets/og/og_default.png`（1200×630・300KB 以内・写真の情報なし）。差し替えるときは同じファイル名で置き換える。LINE・X などは前の画像をしばらく覚えている（キャッシュ）ので、すぐには変わらないことがある
- **robots.txt**：固定（何も禁止せず、sitemap の場所を書くだけ）。ドメイン全体（シミュレーターを含む）に効く
- **sitemap.xml**：リポジトリには置かない。公開（CI の deploy）のたびに `tools/build_sitemap.js` が `diary/entries/index.json` から作る（入口・日記の一覧・日記1件・シミュレーター・動画診断・為替の学習ツール）。日記を足せば手で直さなくてよい。`index.json` に形の違う日付があると作れず、公開されない
- **Search Console**：入口の `<head>` の `google-site-verification` の meta は所有権の確認に使う。**消さない**（消すと確認が外れる）。sitemap は Search Console に `https://yu-ceo.github.io/sitemap.xml` を送る

## 日記の自動公開（`tools/diary_publish.js`）
その日の日記（と図。3版目は2枚まで）だけを、手元のチェック → 確認担当の確認 → push の順で公開する。**CEOの確認は挟まない**（CEO決定 2026-11-16）。どこか1つでも FAIL なら公開しない。

### 最初に1回だけ（CEOの作業・約5分）
1. **機密の言葉の一覧ファイル**を、**運用用のフォルダの外**（このリポジトリの外でもある場所）に作る。1行に1語、`#` で始まる行は説明。GitHub には上げない。場所はこの README・コード・コミットに書かない
2. **環境変数**を2つ設定する（Windows はスタートメニューの「環境変数を編集」、またはコマンドで `setx 名前 "値"`。設定のあとはターミナルを開き直す）
   - `DIARY_CONFIDENTIAL_WORDS_FILE`：1の一覧ファイルの場所
   - `HQ_DIR`：運用用のフォルダの場所（一覧が運用用のフォルダの中に置かれていないか、確認担当の確認の記録がどこにあるかを知るため）
3. GitHub の Secrets の `CONFIDENTIAL_WORDS` に、**1と同じ言葉**を登録する（Settings → Secrets and variables → Actions）。**一覧を更新したら、Secrets も必ず同じ中身に更新する**（push のあとの CI で同じ照合をもう一度するため）
   - 一覧（と Secrets）を更新したら、手元で1回 `node tools/diary_publish.js --check` を動かし、日記以外のファイルで言葉が当たって止まらないかを確かめる（照合は大文字小文字・空白をそろえるので、短い英字の言葉はコードにも当たりやすい）
4. このリポジトリの作成者を決まったものにする：`git config user.name "Yu-CEO"`・`git config user.email "356794411+Yu-CEO@users.noreply.github.com"`

### 毎日の手順（運用担当）
1. 日記を `diary/entries/YYYY-MM-DD.json` に置き、`diary/entries/index.json` の最後に日付を1つ足す（図がある日は `diary/figures/YYYY-MM-DD.svg`、3版目で2枚目がある日は `diary/figures/YYYY-MM-DD-2.svg` も）
2. **② 手元のチェック**：`node tools/diary_publish.js --check`。次をすべて確かめ、PASS なら「指紋」（16文字）が出る
   - 一覧ファイルの場所（指定がない・無い・空・リポジトリの中・運用用のフォルダの中なら「機密の言葉の一覧が正しい場所にありません」で止まる）
   - 変更が「その日の日記1つ＋`index.json` への1行追加＋（あれば）その日の図1つ（3版目は2枚目 `-2.svg` も）」だけか。`-4.svg`・別の日の図・過去の図の変更があれば止まる（〔v5〕3版目は3枚目 `-3.svg` も上げてよい）（ほかの変更があれば「通常の /dev フローとCEO承認が必要です」で止まる）
   - 日付が今日か前の日か／日記と図（2枚目も）の検査（画面・CI と同じ検査）／`figure`・`figure2` と図のファイルが合うか
   - 日記の JSON に `\uXXXX` の書き方（例 `\u3042`）が無いか（日本語や記号はそのまま書く。照合をすり抜けないため）
   - 機密の言葉の照合（`ci/confidential_check.py --words-file`。表示はファイル名と行番号だけで、言葉そのものは出ない）。1行ずつに加えて、全角・半角や空白の違いをそろえた文字と、ファイル全体（JSON は読み込んだあとの文字・SVG は文字をつなげたもの）でも照合する。CI の照合も同じ
   - 3版目の日記は、太字・ハイライトの記号（`**`・`==`）を外した文字でも同じ一覧で照合する（記号で言葉を分けてすり抜けるのを防ぐため）。記号を外した文字は OS の一時フォルダに1項目1ファイルで書き出し、照合のあとに消す（リポジトリには入らない。表示は「日付__項目-番号.txt」と行番号だけ）。CI（`ci.yml` の「機密チェック（記号を外した文字）」）でも同じことをする
3. **③ 確認担当の確認**：日記（図がある日は図を画像として開いて）と指紋を渡し、確認を頼む（3版目は2枚目の図も画像として開く。`takeaway` と、太字・ハイライトの付け方も見る。指紋には2枚目の図も入る）。担当は結果を運用用のフォルダの `security/diary_audit/YYYY-MM-DD.md` に、次の2行を入れて残す
   ```
   判定：PASS
   指紋：（--check が出した16文字）
   ```
   判定の行・指紋の行は**それぞれ1行だけ**にする（2行以上あると④で止まる。書き直すときは追記せず、ファイルを作り直す）。FAIL のときは `判定：FAIL` と理由を書く。確認のあとで日記を1文字でも変えると指紋が変わり、④で止まる（確認し直す）
4. **④ push**：`node tools/diary_publish.js --push`。次の順で進み、どれかで止まれば commit・push しない
   - ②をもう一度（commit の直前の照合）→ ブランチが `main`・手元の `main` が GitHub の `main` と同じ・作成者が決まったもの → ③の記録が PASS で指紋が同じ
   - push 先（`origin`）が公開サイトのリポジトリか
   - 決まったファイルだけを「日記を追加：YYYY-MM-DD」で commit（中身がそのファイルだけか・作成者が決まったものかも確かめ、違えば取り消す。`GIT_AUTHOR_*` などの環境変数は使わない）→ 照合をもう一度（push の直前。止まったら commit を取り消す）→ push
5. GitHub の「Actions」で ✅ を確かめ、CEOに「N日目の日記を公開しました」と伝える

### FAIL のとき・CI で落ちたとき
- どこかで FAIL したら公開しない。CEOに「どの段階で・何が理由で止まったか」を伝え（機密の言葉そのものは書かない）、直した版で②からやり直す
- **CI が ❌ のとき**：サイトには公開されない（`deploy` は `check` 合格が条件）が、リポジトリには載ってしまっている。すぐ運営者とセキュリティ担当に伝え、セキュリティ担当の判断で取り下げる（元に戻すコミット。必要なら履歴の消去）。取り下げは通常の /dev フロー（CEO承認）で行う
- さかのぼりの日記・コードや設定の変更は、このコマンドでは上げられない（通常の /dev フロー）

## 日記のデータの形（`diary/entries/YYYY-MM-DD.json`）
日記の形は3つ。`format` を見て見分ける（`js/diary_format.js`）。
- **3版目**（`"format": 3`）：**2026-11-19 以降の日記はこの形だけ**（2版目の最後の日は `js/diary_format.js` の `DIARY_STORY_LAST_DATE`＝2026-11-18 の1か所だけに書いてある）。2版目に、太字・ハイライト・今日の学び・図2枚が足せる
- **2版目**（`"format": 2`）：2026-11-16〜2026-11-18 の日記だけ（公開済みの Day 3〜5。書き直さない・今の見た目のまま）。その日の会議でいちばん盛り上がった1つの話題を、「何が問題だったか → 役員の意見 → Yu の決定 → 結果と学び」の1本の話として書く
- **旧形式**（`format` を書かない）：**2026-11-15 以前の日記だけ**（公開済みの Day 1・Day 2。書き直さない）。2026-11-16 以降に旧形式で書くと検査で止まる

### 新しい形（`"format": 2`）
| 項目 | 内容 | 決まり |
|---|---|---|
| `format` | 新しい形の印 | 数字の `2`（文字の `"2"` は不可） |
| `date` | 会議の日 | `YYYY-MM-DD`。ファイル名と同じ。2026-11-16 以降 |
| `title` | 話題の見出し | 空でない・40文字以内 |
| `summary` | 秘書の一言まとめ（一覧・パネルの抜粋） | 空でない・120文字以内 |
| `problem` | 何が問題だったか（段落の配列） | 1〜3個・各200文字以内 |
| `lines` | 役員の意見 `{ "speaker": 話者, "text": セリフ }` の配列 | 2〜8個・各80文字以内。話者は旧形式と同じ9人だけ |
| `decision` | Yu の決定（1つ） | 空でない・120文字以内。保留にしたときは「保留にした」と書く |
| `result` | 結果と学び（文字の配列） | 1〜3個・各120文字以内 |
| `pick` | 冒頭の「今日の一言」のセリフの番号 | 旧形式と同じ（書かなくてよい） |
| `figure` | 図の説明 `{ "alt": 図の説明文, "caption": 図の下の短い説明 }` | 図がない日は書かない。`alt` 200文字以内（図の中の文字の要点を必ず入れる）・`caption` 60文字以内。図の場所は書かない（`diary/figures/<date>.svg` に決まっている） |

- 上の項目以外と、旧形式の項目（`agenda`・`decisions`・`lessons`）は書かない（検査で止まる）。本文の合計（見出し・抜粋・問題・意見・決定・結果）は300〜1,500文字。図の説明と図の中の文字は数えない
- 1件のページは「紺の帯（今日の一言・Yuの決定・今日の参加）→ 道しるべ（問題›意見›決定›結果）→ 01 何が問題だったか → 02 役員の意見 → 03 Yuの決定 →（図）→ 04 結果と学び」の順で出る。一覧・入口のパネルは旧形式と同じ見た目（図は出さない）

### 3版目（`"format": 3`）
2版目と同じ項目に、次が加わる・変わる。

| 項目 | 内容 | 決まり |
|---|---|---|
| `format` | 3版目の印 | 数字の `3`（文字の `"3"` は不可）。日付は 2026-11-19 以降 |
| `takeaway` | 今日の学び（読み終わって持ち帰る1文） | 書かなくてよい。書くなら記号を除いて60文字以内・1文（「。」「！」「？」は最後に1つまで）・改行なし。本文の最後の黄色い枠に出る |
| `figure3` | 3枚目の図の説明 `{ "alt", "caption" }`（v5）。書かなくてよい。意見と決定のあいだに出る。ファイルは `diary/figures/<date>-3.svg` |
| `figure2` | 2枚目の図の説明 `{ "alt", "caption" }` | 書かなくてよい（`figure` なしで `figure2` だけの日も可）。結果のすぐ下に出る。ファイルは `diary/figures/<date>-2.svg` に決まっている |
| `hero` | 入口画像の説明 `{ "alt" }`（3版目のみ） | 書かなくてよい。強調の記号は不可・200文字まで。画像は `diary/heroes/<date>.jpg`（1280×720・JPEG・400KB以下）に決まっている |

- **太字・ハイライト**：`problem`・`lines` の `text`・`decision`・`result`・`takeaway` の中だけで、`**太字**` と `==ハイライト==` の2種類が書ける（HTML は書けない）。`title`・`summary`・`speaker`・`figure`／`figure2` の `alt`・`caption`・図の中の文字には書けない
  - 形の誤りで止まる：閉じていない（`**大事`）・入れ子や重なり（`**a==b==**`）・空（`****`・`** **`）・3つ以上続く（`***`・`===`）・1つの文字の項目（配列なら1要素）をまたぐ強調。1つだけの `*`・`=`（`A=B`）は普通の文字
  - 数の上限：ハイライトは1記事に1か所まで、太字は「`problem` 全体／`lines` 全体／`decision`／`result` 全体／`takeaway`」のブロックごとに1か所まで
  - 文字数は記号を除いて数える（各項目の上限・合計の300〜1,500文字）。記号を含めたもとの長さは、上限＋20文字まで
  - 「公開してはいけない書き方」の検査は、もとの文字と記号を外した文字の両方にかける（`3**万**` のように記号で区切ってすり抜けるのを止める）
- 画面：3版目だけ、太字は `strong`・ハイライトは `mark`（黄色の背景＋濃い文字）で出る。文字は `createTextNode`・`textContent` で入れ、`innerHTML` は使わない。2版目・旧形式の文に `**` があっても、記号のまま文字で出る
- 1件のページは「紺の帯 → 道しるべ（問題›意見›決定›結果›学び）→ 01 何が問題だったか → 1枚目の図 → 02 役員の意見 → 03 Yuの決定 → 04 結果 → 2枚目の図 → 今日の学び → オープンチャットへの出口」の順。一覧・入口のパネルは今までと同じ見た目（記号・図は出ない）

### 日記の入口画像（`diary/heroes/YYYY-MM-DD.jpg`・3版目のみ）
- `hero` を書いた日だけ、1件のページの一番上（`<img>`・alt は `hero.alt`）と、入口の「最新の日記」カード・日記一覧のカードの一番上（飾り扱いで alt なし）に出る。`hero` のない日は今までどおり。読み込めないときは画像だけが隠れる
- 自動公開（`tools/diary_publish.js`）：その日の新しい `diary/heroes/<日付>.jpg`（0〜1つ）を上げてよいファイルに足す。別の日・別の名前・別の拡張子は止める。`hero` とファイルの有無が合わないとき、先頭が JPEG の印（FF D8 FF）でないとき、400KB を超えるときも止める

### 日記の図（`diary/figures/YYYY-MM-DD.svg`・3版目は `YYYY-MM-DD-2.svg` も）
- 変化の前後・比較・流れの説明がある回だけ。2版目は1日1枚まで、3版目は3枚まで（1枚目＝問題の下、3枚目＝意見と決定のあいだ、2枚目＝結果の下）。`figure` がある日にだけ `<日付>.svg`、`figure2` がある日にだけ `<日付>-2.svg` を置く（過不足があるとテストが失敗する）。`-1`・`-4` など決まっていない名前の図があっても失敗する。2枚目にも下の機械の検査が同じようにかかる。図の中の文字に `**`・`==` は書けない
- ページでは必ず `<img>` で表示する（図の中のプログラムは動かない）。読み込めないときは図と説明だけが隠れ、本文は出る
- 機械の検査（`js/diary_svg_check.js`。テスト・CIで実行）で止まるもの：
  - 許可した要素（`svg` `g` `title` `desc` `defs` `rect` `circle` `ellipse` `line` `polyline` `polygon` `path` `text` `linearGradient` `radialGradient` `stop` `marker`）と、許可した属性以外。`on…`・`href`・`style` 属性・`tspan`・`use`・`image`・`script` などはすべて不可
  - 色の属性（`fill`・`stroke`・`stop-color`・`marker-start`・`marker-end`）は `#` から始まる色（`#fff`・`#ffffff`）・`none`・`currentColor`・`transparent`・`white`・`black`・`url(#名前)` だけ（`marker-*` は `url(#名前)` か `none`）。`(` は `url(#名前)` と `transform`（`translate(…)` などの決まった形）の中だけ
  - `url(…)` は同じファイルの中の `url(#名前)` だけ（`URL(`・`\` を混ぜた書き方も止まる）。`font-family` は `sans-serif`・`serif`・`monospace` だけ。いちばん外側の `<svg>` に `xmlns="http://www.w3.org/2000/svg"` と `viewBox` が必要
  - `<!DOCTYPE`・`<!ENTITY`・`<?xml-stylesheet`・`<![CDATA[`・コメント・`&`（使いたいときは全角の「＆」）。先頭の `<?xml version="1.0" encoding="UTF-8"?>` だけは可
  - 文字は `<text>`・`<title>`・`<desc>` の中だけ。**1つの `<text>` は1行で書き（途中で改行しない）、30文字以内**。1つの言葉を2つの `<text>` に分けない（機密の言葉の照合が1行ずつのため）。図の中の文字の合計は200文字以内
  - 図の中の文字にも、日記の文字と同じ「公開してはいけない書き方」の検査がかかる（1つずつと、全部つなげた文の両方）。ファイルは30KB以内
- 描き方の決まり（人の目で確認）：オリジナルの絵だけ。金額・資産・収支・進み具合を大きさで表す図（棒グラフ・円グラフ・メーターなど）や、地域・物件が分かる絵は描かない。見本は `tests/fixtures/diary_figures/2026-11-17.svg`（幅300の座標・文字15以上）

## ページの軽さ（2026-11-17）
GitHub Pages が重く感じるようになったため、見た目と動きを変えずに、読み込みを減らした。
- **CSS・JS をまとめるのは公開のときだけ**：リポジトリの `css/`・`js/` は機能ごとに分けたまま（読みやすさのため）。CI の deploy で `tools/build_bundle.js` が、ページごとに CSS を1つ・JS を2つにまとめる。アクセス解析の JS を別にするのは、表示の JS がエラーで止まっても計測は動かすため（4ページで同じファイルなので2ページ目からは保存された物を使う）。まとめたファイルの名前には中身の印（ハッシュ）が入るので、更新したのに古いファイルが使われ続けることがない
- **script に defer**：HTML を読み終えてから、書いた順に動かす（手元で開いたときも公開のときも同じ）
- **Yu の画像**：`assets/yu.webp`（約94KB）を先に使い、WebP を表示できないブラウザだけ `yu.jpg`。幅・高さを書いて場所を取り、役員の区画なので後で読み込む
- **ほかの画像**：ツールのスクリーンショット・日記の図は `loading="lazy"`（見える場所に近づいてから読み込む）。最初の画面では読み込まない
- **新しい JS・CSS を足すとき**：今までどおり HTML に `<script src="js/○○.js" defer></script>`・`<link rel="stylesheet" href="css/○○.css">` を1行で書けば、公開のときに自動でまとめに入る（計測用は名前を `analytics_` で始める）

## 注意
- このサイトの計算ツールは計算するだけのもので、特定の商品や売買をすすめるものではありません（投資の助言ではありません）。
- 外部ライブラリはありません。入力内容の保存・送信もしません。読み込むのは同じサイトのファイルと、次の例外（どちらも画像だけ）です。
- **例外（4ページ）：アクセス解析**：このサイトでは、ページごとの閲覧数と、どのサイトから来たかを知るために、アクセス解析サービス（GoatCounter）を使っています。ページを開くと、そのサービスと通信し、見ているページの場所・来る前のサイト名・IPアドレス・ブラウザの種類が届きます。Google のサービスは Cookie を使うことがあります。個人を特定する情報は集めません。ブラウザで「トラッキングしない」を設定している場合は計測しません。止め方は上の「アクセス解析（GoatCounter）」（`ANALYTICS_ENABLED` を `false`）
- **例外（入口ページのみ）**：道具箱の紹介リンクのカードに置く、ASPの計測用の小さな画像（1×1）。ページを開くと、そのASP（今は A8.net ともしもアフィリエイト）と通信します（アクセスの情報が届き、Cookieが使われることがあります）。読み込み先は `ASP_LIST` の `beaconHosts` に限り、外部のスクリプト・`<iframe>` は使いません。日記のページには置きません
- 道具箱は、Yuが実際に使っている物の体験談です。アフィリエイト広告（PR）を含みます。特定の金融商品や売買をすすめるものではありません（投資の助言ではありません）。
- 日記は、AIを使った役員会議の記録を公開用に書き直したものです。金額などの数字は伏せています。登場する役員はAIのキャラクターです。
